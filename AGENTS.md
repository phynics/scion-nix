# Agent guide for scion-nix

This file is for coding agents and contributors who change this repository. The user-facing documentation is in [docs/](docs/README.md). Keep both in sync when behavior changes.

## What this repository is

A Nix flake that packages [Scion](https://github.com/GoogleCloudPlatform/scion) (Google's agent orchestration CLI and server). It also delivers Scion's container images and provides NixOS and nix-darwin modules for Scion's four run modes:

- Local
- Workstation
- Single-node hosted
- HA hosted

Do not confuse Scion with SCION, the internet architecture. nixpkgs has an unrelated `services.scion` networking module and `scion` package. That is why this flake's CLI package and option are named `google-scion`. The `services.scion.{workstation,hub,broker}` names do not collide with nixpkgs.

## Map

| Path | Contents |
|---|---|
| `flake.nix` | Outputs. It asserts that `image-manifest.json` and `upstream.json` pin the same revision. |
| `upstream.json` | `version`, `rev`, `imageTag` (harness image tag), `binaryRelease` (GitHub release tag of the native tarballs). |
| `image-manifest.json` | Per-platform digests of the upstream-built images. Generated by `.github/workflows/images.yml`; never hand-edit a digest. |
| `nix/package.nix` | Source build: npm web client, then Go with the web assets embedded. Holds the Hub fixes as `substituteInPlace` calls. |
| `nix/published-binaries.nix` | Prebuilt release tarballs, with SHA-256 hashes for each platform. |
| `nix/pull-images.nix` | `scion-pull-images`: pull by digest, retag as `<registry>/scion-<harness>:latest`. Exposes `passthru.harnessNames`. |
| `nix/server-image.nix` | `dockerTools.buildLayeredImage` of the Hub, Web, and Broker server. Linux only. |
| `nix/modules/nixos.nix` | Every mode: `programs.google-scion`, `services.scion.{workstation,hub,broker}`. |
| `nix/modules/darwin.nix` | Local and Workstation (launchd user agent). |
| `nix/tests/modules.nix` | Evaluation tests for every mode and for the rejected combinations. |
| `nix/tests/image-puller.nix` | Runs the puller against a fake `podman`. |
| `examples/*.nix` | Single-node and HA configurations. Imported by the tests, so they must keep evaluating. |
| `patches/*.patch` | Applied to upstream by `images.yml` before the image build. |
| `docs/` | Human documentation. `docs/reference.md` mirrors the module options by hand. |

## Invariants

Do not break these:

1. **Pins stay consistent.**
   - `upstream.json.rev` must equal `image-manifest.json.upstreamRev` and the `scion-src` input commit.
   - `imageTag` must match the tag the images were pushed with.
   - Change these only through the procedure in [docs/operations.md](docs/operations.md#upgrading-scion).
2. **No secrets in the store.**
   - Options that carry secrets are runtime *paths* (`environmentFile`, `settingsFile`), typed `str`, never `path`, so they are not copied into the store.
   - Never read a secret file at evaluation time. Never interpolate secret values into units, scripts, or command lines.
3. **Accounts and user state are the operator's.**
   - Modules never create users.
   - Modules never write to `~/.scion/settings.yaml` except for the guarded symlink from `settingsFile`, which refuses to replace a regular file.
4. **Native services, pinned images.**
   - Modules run the host binary under systemd or launchd, never a Scion server container.
   - Agent images are pulled by digest, never built on the user's machine.
   - Components that do not run agents (a Hub without a broker) must not enable a container runtime or pull images.
5. **Mode semantics follow upstream.**
   - Workstation uses `scion server start` without `--hosted`.
   - Hosted components use `--hosted` with explicit `--enable-*` flags.
   - HA means the `postgres` driver, a shared `hubId`, GCS storage, and no embedded broker.
   - Check upstream `cmd/server.go`, `cmd/server_foreground.go`, and `pkg/config/hub_config.go` at the pinned revision before adding a flag or `SCION_SERVER_*` variable.
   - Environment keys map through `envKeyToConfigKey`, so `SCION_SERVER_STORAGE_LOCAL_PATH` does **not** reach `storage.localPath`. Prefer CLI flags.
6. **Assertions over surprises.** An invalid combination fails evaluation with a message that says what to do. When you rename or remove an option, use `mkRenamedOptionModule` or `mkRemovedOptionModule`.

## Module conventions

- Compose a unit from fragments with `mkMerge`, never `//` or `recursiveUpdate`. Those replace lists such as `after` and `wants`; that bug once dropped the `linger-users.service` ordering.
- Build command lines as lists and render them with `lib.escapeShellArgs`.
- Put rootless Podman settings on every unit that touches Podman, through `runtimeUnit`: `Delegate=yes`, `PODMAN_SYSTEMD_UNIT=%n`, and ordering after `linger-users.service`.
- Default the Hub to `google-scion-source`, which carries the fixes. The CLI, the workstation, and the broker default to the prebuilt `google-scion`.
- launchd agents get an explicit `PATH`. Scion shells out to `git` and `podman`.

## Validating a change

Run what CI runs, for your platform:

```sh
nix flake check                                   # module tests, puller test, package builds, server image (Linux)
nix build .#checks.x86_64-linux.modules           # fast: module evaluation tests only
nix build .#checks.x86_64-linux.image-puller-behavior
nix build .#scion-server-image && podman load < result
```

Any change to a module needs a matching assertion in `nix/tests/modules.nix`, for both the accepted and the rejected configurations. Use the `rejected` helper for configurations that must fail. If the change alters behavior, also update `docs/reference.md` and the relevant guide.

### Smoke test for server changes

Start the Hub the way the service or image does, and check the endpoints and a real asset:

```sh
bin=$(nix build .#google-scion-source --print-out-paths --no-link)/bin/scion
tmp=$(mktemp -d)
HOME=$tmp SCION_SERVER_SESSION_SECRET=x $bin server start --foreground --hosted --enable-hub --enable-web \
  --host 127.0.0.1 --web-port 18080 --db $tmp/hub.db --storage-dir $tmp/storage &
curl -s -o /dev/null -w '%{http_code}\n' localhost:18080/healthz          # 200
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' localhost:18080/assets/main.js   # 200, ~140 KB
```

In hosted mode, `/` returns 401 without a session. `/login` is public.

### Environments with restricted network access

When GitHub archive downloads are blocked but `git clone` works, clone the inputs and override them. With a partial clone (`--filter=blob:none`), check out the pinned commit first so its blobs exist:

```sh
git clone https://github.com/GoogleCloudPlatform/scion.git /tmp/scion && git -C /tmp/scion checkout <rev>
nix flake check --override-input scion-src "git+file:///tmp/scion?rev=<rev>"
```

Two more constraints:

- `nix flake check --all-systems` evaluates about ten NixOS systems per platform and can run out of memory on a 16 GB host. Check one platform at a time instead.
- With `sandbox = false`, remove a stray `/homeless-shelter` before building Go modules.

## Upstream reference points

These paths are in the Scion repository at the pinned `rev`:

- Mode definitions: `docs-site/src/content/docs/choosing-a-mode.md`, `GLOSSARY.md`
- Server flags: `cmd/server.go`; configuration loading and HA preflight: `cmd/server_foreground.go`
- Server settings and environment mapping: `pkg/config/hub_config.go`, `docs-site/src/content/docs/reference/server-config.md`
- Image targets: `image-build/scripts/lib/targets.sh`; harness image names: `harnesses/*/config.yaml`

## Commits and pull requests

- Keep each change focused.
- Explain behavior changes and migrations in the commit body.
- Never commit generated digests or hashes you did not obtain from a real build or workflow run.
